年初习惯性地回头看一眼,这一年技术圈过得不算平静。写下来不是为了立 flag,是想把几个真正改变工作方式的东西,拎出来看看清楚。

## 几个绕不开的关键词

**AI 辅助编程**:这是绕不开、也躲不掉的话题。从自动补全到结对编程,AI 把大量重复劳动接了过去——写样板、写测试、写那些"闭着眼都知道怎么写"的胶水代码。但奇怪的是,省下来的时间并没有让事情变轻松,反而逼着人去面对更难的问题:**理解业务、做架构决策、判断 AI 给的方案对不对**。这些才是现在真正值钱的能力。

**云原生**:容器和编排已经成了默认基建。Kubernetes 从"要学的东西"变成了"必须会的东西",就像几年前学 Git 一样——不再是加分项,是入场券。

**可观测性**:日志、指标、链路追踪三件套,成了排查问题的标配。没有可观测性的微服务,出了事就是抓瞎。这一年越发觉得,**"出了问题能快速定位"这件事,和"不出问题"几乎同样重要**。

## AI 到底改变了什么

很多人担心 AI 会抢饭碗,但回头看一年,体感更准确的说法是:**AI 重新分配了注意力的权重**。

| 过去花时间的 | 现在花时间的 |
|------|------|
| 记 API 细节、查语法 | 定义清楚"要解决什么" |
| 手写大量样板代码 | 审查 AI 产出的代码质量 |
| 从零搭脚手架 | 做架构权衡和取舍 |

写代码的门槛确实降低了,但"把需求翻译成正确方案"的门槛一点没降,反而更高了。因为现在的问题更复杂了,而能一眼看穿问题本质的人,依然稀缺。

> AI 不是替代思考,是把思考逼到了更高的层面。

一个很具体的体会:现在问一句"这段代码哪里不对",比从前"从头写一遍"更需要功力和判断力。以前靠手熟,现在靠眼力。

## Java 与后端生态的变化

Java 生态这一年谈不上"改朝换代",更多是**慢下来、变实了**:

- **虚拟线程(Project Loom)落地了**,同步写法拿到了接近异步的吞吐,很多"为了性能硬写成响应式"的代码,开始有理由重新回到简单直白的风格。
- **Spring Boot 3 成为主流**,迁移阵痛过了之后,大部分项目稳定在了新基线。
- **GraalVM 原生镜像**从玩具走向了生产,冷启动快到可以做 Serverless,虽然 build 的复杂度和踩坑成本依然劝退。

对做后端的人来说,一个越来越明显的信号是:**框架在收敛,能力在向"能不能讲清楚系统"转移**。工具链成熟了,瓶颈就回到了设计上。

## 踩过的坑

今年最大的几个教训,都不是"不会",而是"没想清楚就动手":

- **过度设计**:一个小需求硬套了一堆模式,最后连自己都看不懂,返工比当初直接写还慢。
- **忽略监控**:功能上线了才发现没有告警,出问题全靠用户反馈,被动得像消防员。
- **迷信工具**:以为上了某个"银弹"框架就能解决所有问题,结果坑更多,还得额外维护一层抽象。

这三条有个共同点:**都以为省了思考的功夫,最后都在还债**。

## 一点个人思考

这一年学到的最有用的一件事,反而是**慢一点**。

技术更新太快,追不完,追到最后容易焦虑。后来想明白一个道理:与其焦虑,不如抓住那些不变的东西——**扎实的底层原理、清晰的工程思维、持续学习的能力**。这些不会因为某个框架过时而过时。

写作也是这一年捡起来的习惯。把学到的东西写下来,输出倒逼输入。写博客这件事,本质上是在逼自己把一个模糊的认知,整理到能讲给别人听的程度——这个过程本身,就是最好的学习。

## 新的一年

想深耕的几个方向,不贪多:

1. **深入 JVM**:不满足于会用,想真正理解底层——GC、内存模型、字节码,这是后端的"内功"。
2. **系统设计**:从单机思维走向分布式思维,学会在一致性、可用性、性能之间做权衡。
3. **写作沉淀**:继续像这个博客一样,把学到的写下来,让输入真正留下来。

## 写在最后

一年下来最大的感受,浓缩成一句:

> 技术是变化的,但把技术用好所需的那份冷静和判断,是不变的。

种一棵树最好的时间是十年前,其次是现在。新的一年,继续写代码,继续记录,继续把那些不变的功夫练扎实。
